Note. Each row is the median of 3 runs, with the lowest and highest in brackets; the cold start is one run. Times are wall-clock seconds from the moment a message enters PIP's pipeline, run exactly as the chat uses it: first word = the first streamed token, full answer = the whole reply. Before = PIP as shipped (commit 6a51798, 2026-10-21): it called Ollama at "localhost", which on this PC resolves to the IPv6 address ::1 first while Ollama listens on 127.0.0.1 only, so every request waited 2.04 s before falling back, twice per message (the availability check and the answer). After = the D-50 fix, Ollama called at 127.0.0.1 (commit 52db009 plus the fix, 2026-10-22). Over all 24 runs the first word took a median 4.48 (4.30–7.29) s before and 0.36 (0.26–0.48) s after; the day before the fix, the test script forcing 127.0.0.1 without changing PIP had predicted 0.41 (0.30–0.66) s. PIP's own steps before the model (Stages 0–8, the availability check included) took 2.32 (2.14–5.14) s before and 0.26 (0.15–0.32) s after. With the model handed in directly (no availability check, still localhost) the first word took 2.4 s, one 2 s wait. Full-answer times also follow the answer's length, which differed between runs and days even at temperature 0 (the explanation was 262 or 662 tokens before and 395 after), so the first word is the clean comparison; tokens written and speed are medians over both. The answer cache was emptied before every timed question. Test PC: Intel Core i9-14900HX, 16 GB RAM, NVIDIA GeForce RTX 4060 Laptop GPU (8 GB), Windows 11 Home.
